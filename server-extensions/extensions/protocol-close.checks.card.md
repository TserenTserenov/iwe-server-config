# protocol-close.checks.card.md — сверка карточки РП с шаблоном при закрытии сессии

> WP-503 Ф111, код изменения Ц38-20, решение пилота 23.11. Шаблон: `DS-my-strategy/docs/INBOX-CONVENTION.md`, раздел «Шаблон карточки РП».
> Мягкая проверка: закрытие она не блокирует. Результат — одна строка на РП в отчёте закрытия.

**Зачем.** К концу сессии агент знает РП лучше, чем при открытии. Пустые поля карточки заполняются сейчас, пока контекст свежий: следующая сессия начнёт с готовой карточки.

## Когда выполнять

Для каждого РП, над которым сессия работала (по объявленному намерению и по заметкам сессии). РП, который сессия только читала, пропустить.

## Шаги по каждому РП

1. **Показать пробелы по шаблону.** Карточка лежит в репозитории управления; если сессия работала в отдельной временной копии, передать её путь:

   ```bash
   IWE_ROOT="${IWE_WORKSPACE:-${WORKSPACE_DIR:-$HOME/IWE}}"
   GOV="${IWE_GOVERNANCE_REPO_PATH:-$IWE_ROOT/${IWE_GOVERNANCE_REPO:-DS-my-strategy}}"
   python3 "$GOV/scripts/check-wp-card-schema.py" --repo "$GOV" --all --template-details | grep "inbox/WP-<N>/"
   ```

   Пусто — карточка по шаблону полная, шаг закончен.

2. **Поправить то, что изменила сессия:** `status`, `status_note`, фазы и их связи, `related`, `budget`, раздел «Осталось». Эти правки закрытие делает и без шаблона; здесь проверить, что они внесены.

3. **Заполнить пустые смысловые поля по содержимому карточки**, ничего не выдумывая:
   - `artifact_kind` — значение из перечня в блоке `card-template` соглашения о папках РП (`docs/INBOX-CONVENTION.md`);
   - `artifact_home` — хранилище и путь, где лежит или будет лежать результат;
   - раздел «Суть в трёх строках»: что это, что создаётся, для кого.

   Если из карточки ответ не следует, поле оставить пустым и записать вопрос в «Осталось» строкой «Нужно уточнить: …».

4. **Ящик входящих.** Файл `inbox/WP-<N>/INBOX.md` обязателен у каждого РП. Нет — создать пустой с тем же заголовком, который пишет `wp-inbox.sh`:

   ```bash
   printf '# Входящие РП-%s\n\n> Только дописывание. Статус записи меняет скрипт wp-inbox.sh (mark), не правка текста.\n' "<N>" > "$GOV/inbox/WP-<N>/INBOX.md"
   ```

5. **Записать израсходованное время (вручную, решение пилота 23.11, РП-503 Ф112).** Время сессии прибавляется к `budget_spent` карточки РП, на который открыта сессия (поле `wp` её отметки). По остальным РП, которых сессия касалась, время не пишется, если пилот не назвал разбивку словами.

   **Сколько.** Если пилот назвал число («потратили два часа») — взять его. Иначе считать по часам: от `opened_at` отметки сессии до сейчас, округлить до 0,25 ч вверх. Паузы агент не знает: при очевидной паузе (сессия простояла ночь, пилот отходил) спросить пилота одной строкой «сколько записать?» и взять ответ. Отметку своей сессии искать по её `slug` (он назван при открытии сессии). Каждый блок кода ниже запускать целиком, в одном вызове оболочки: переменные между вызовами не сохраняются.

```bash
IWE_ROOT="${IWE_WORKSPACE:-${WORKSPACE_DIR:-$HOME/IWE}}"
SESSION_FILE=$(grep -l -x "slug: <slug своей сессии>" "$IWE_ROOT"/.iwe-runtime/sessions/*.open | head -1)
python3 - "$SESSION_FILE" <<'PY'
import re, sys, datetime
opened = re.search(r"^opened_at: (\S+)", open(sys.argv[1], encoding="utf-8").read(), re.M).group(1)
delta = datetime.datetime.now(datetime.timezone.utc) - datetime.datetime.fromisoformat(opened.replace("Z", "+00:00"))
print(f"{-(-delta.total_seconds() // 900) * 0.25:g}")
PY
```

   **Куда.** Записывать только через общую точку правки карточек, чтобы две параллельные сессии не затёрли друг друга: снять отпечаток карточки, собрать новый файл, подменить карточку с проверкой отпечатка. Подмена идёт только если новый файл собран и не пуст. Конфликт отпечатка (карточку успела изменить другая сессия) — перечитать карточку и повторить с начала. Поля нет — скрипт добавляет `budget_spent` сам. Часы пишутся десятичным числом, запятая тоже принимается (`1,5`).

```bash
IWE_ROOT="${IWE_WORKSPACE:-${WORKSPACE_DIR:-$HOME/IWE}}"
GOV="${IWE_GOVERNANCE_REPO_PATH:-$IWE_ROOT/${IWE_GOVERNANCE_REPO:-DS-my-strategy}}"
CARD="$GOV/inbox/WP-<N>/WP-<N>.md"
TMP=$(mktemp)
HASH=$(sha256sum "$CARD" | cut -d' ' -f1)
if python3 - "$CARD" "<часы, например 1.5>" > "$TMP" <<'PY' && [ -s "$TMP" ]
import re, sys
text = open(sys.argv[1], encoding="utf-8").read()
add = float(sys.argv[2].replace(",", "."))
end = text.index("\n---", 4)               # end of the frontmatter; the body is never touched
head, rest = text[:end], text[end:]
m = re.search(r'^budget_spent:[ \t]*"?([0-9.]+)h"?[ \t]*$', head, re.M)
if m:
    total = float(m.group(1)) + add
    head = head[:m.start()] + f"budget_spent: {total:g}h" + head[m.end():]
else:
    total = add
    head += f"\nbudget_spent: {total:g}h"
sys.stdout.write(head + rest)
print(f"всего {total:g}h", file=sys.stderr)
PY
then
  bash "$IWE_ROOT/scripts/session-guard.sh" wp-context-guarded-edit "$CARD" --expected-hash "$HASH" -- cp "$TMP" "$CARD"
else
  echo "budget_spent не записан: скрипт сборки карточки не отработал, карточка не тронута"
fi
rm -f "$TMP"
```

   Строка «всего …h» из вывода скрипта идёт в отчёт закрытия: «РП-N: +1,5 ч, всего 6,5 ч».

   **Предел точности.** Простой между репликами при счёте по часам засчитывается как работа; сессия, оборвавшаяся без закрытия, времени не запишет. Параллельные сессии одного РП защищены проверкой отпечатка карточки: проигравшая повторяет запись.

## Что записать в отчёт закрытия

Одна строка на РП: «Карточка РП-N по шаблону: полная» или «Карточка РП-N: не хватает …; причина: …».

## Границы

- Карточка заморожена или недоступна для правки в этой сессии: строка в отчёте и вопрос в «Осталось», шаг не обходить.
- Проверка идёт режимом отчёта (`check-wp-card-schema.py`): код возврата всегда 0, блокировки нет. Запись времени тоже не блокирует закрытие: нельзя записать — строка в отчёте и вопрос в «Осталось».
