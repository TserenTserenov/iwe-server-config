# Strategy Session — секция здоровья (РП-470)

## Секция «Здоровье (РП-470)» в discovery-контекст (БЛОКИРУЮЩЕЕ при наличии базы)

**Когда выполнять:** Шаг 3.2 (режим discovery, «состояние пилота изменилось»/первый месяц) — перед `/discovery-session`, как один из входных фактов о состоянии пилота, вместе со state-card.

**Автовызов не подключён (Extensions Gate, 25.07):** в отличие от Week Close/Month Close, SKILL.md `strategy-session` пока не читает `load-extensions.sh strategy-session after` — это платформенный (L1) файл, правится только через `update.sh`/автора (`author_mode`), не напрямую агентом. До промоции — Стратег читает этот файл вручную на шаге 3.2 при входе в discovery-режим и выполняет команду ниже сам.

**Дизайн (решение пилота 25.07):** те же три метрики, что в Day Open/Week Close/Month Close, окно — последние 30 дней от даты сессии (не календарный месяц, в отличие от Month Close — Strategy Session читает недавнее состояние, а не закрывает период). Секция самостоятельная, не входит ни в какое решающее правило («стоп-лист калибр-разрыва» упоминался как кандидат в WP-470 Ф5, но решение не принято) — просто делает свежий тренд видимым в момент, когда обсуждается состояние пилота, без открытия отдельного файла.

**Что сделать:**

```bash
PERIOD_END=$(date +%Y-%m-%d)
PERIOD_START=$(date -v-30d +%Y-%m-%d)  # macOS date; 30 дней назад
bash "$HOME/IWE/extensions/strategy-session.summary-extra.sh" "$PERIOD_START" "$PERIOD_END"
```

Вывести результат прямо в контекст обсуждения (не файл-артефакт — Strategy Session не пишет отдельный отчёт для этой секции, только использует как входные данные для дискуссии о состоянии).

**Инвариант:**
- Данных нет → скрипт сам пишет честную заглушку.
- Вывод детерминированный (SQLite), не переписывается LLM.
- Скрипт author-only (личные данные), в FMT-exocortex-template не поставляется.

**Известное дублирование:** тот же тип данных (30-дневное окно против календарного месяца в MonthClose) — осознанное решение 25.07, не забытый хвост.
