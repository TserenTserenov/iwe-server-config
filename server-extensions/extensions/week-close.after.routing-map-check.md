# Week Close — после основного алгоритма

## Шаг B1. Лёгкая сверка карты маршрутизации знаний (DP.KR.001)

**Когда выполнять:** после шага 4 (аудит memory) и/или шага 9 (Extensions after), перед финализацией (шаг 10 запись WeekReport).

**Зачем:** карта маршрутизации (`PACK-digital-platform/pack/digital-platform/02-domain-entities/DP.KR.001-knowledge-routing.md`) дрейфует тихо — новые типы контента появляются в практике и закрепляются, но не попадают в карту, пока кто-то не сверит вручную (см. WP-477: 3 непокрытых типа накопились за 2 месяца без единой ревизии).

**Что сделать (~5 мин):**

1. Собрать новые файлы за неделю в DS-*/PACK-* репо:
```bash
for repo in $(ls ~/IWE/ | grep -E '^(DS-|PACK-)'); do
  [ -d ~/IWE/$repo/.git ] || continue
  git -C ~/IWE/$repo log --since="7 days ago" --name-only --diff-filter=A --pretty=format: 2>/dev/null | grep -v '^$'
done | sort -u
```
2. Глазами: встречается ли новый **паттерн** (не единичный файл, а тип — новая папка/формат имени, повторившийся ≥2 раза) без соответствующей строки в §5.2-§5.8 DP.KR.001?
3. Нет нового типа → отметить ✅, ничего не делать.
4. Есть новый тип → **не чинить прямо здесь**. Одна строка в Week Close-отчёте: «Карта DP.KR.001 не покрывает: `<тип>`» — решение чинить сейчас vs отдельным РП за пилотом.

**Не дублирует Routing Gate (DP.SC.036):** тот — point-lookup для одного файла в момент записи. Этот шаг — периодическая batch-сверка карты целиком с практикой месяца/недели.

**Связь:** глубокая ревизия §8 «Известные пробелы» — на Month Close (`month-close.after.routing-map-review.md`), не здесь.
