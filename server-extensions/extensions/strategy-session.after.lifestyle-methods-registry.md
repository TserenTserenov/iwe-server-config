# Strategy Session — секция методов стиля (РП-513)

## Секция «Методы стиля (РП-513)» в discovery-контекст

**Когда выполнять:** тот же шаг, что секция «Здоровье» (`strategy-session.after.health.md`) — Шаг 3.2 (режим discovery, «состояние пилота изменилось»/первый месяц), перед `/discovery-session`, как один из входных фактов о состоянии пилота.

**Автовызов не подключён** (тот же статус, что у `strategy-session.after.health.md`, Extensions Gate 25.07): SKILL.md `strategy-session` пока не читает `load-extensions.sh strategy-session after` — это платформенный (L1) файл, правится только через `update.sh`/автора (`author_mode`). До промоции — Стратег читает этот файл вручную на шаге 3.2 и выполняет действие ниже сам.

**Что сделать:**

1. Прочитать `DS-my-strategy/docs/lifestyle-methods-registry.md`.
2. Пройти колонку «Критерий пересмотра (черновик)» — для каждой строки, кроме осознанно выведенных (статус «выведено»), проверить, не сработал ли критерий, по фактам сессии/недели. Статусы «сделано (стиль)», «сделано (мастерство)», «сделано (стиль/мастерство)» и «в работе» проверяются все — ни один не пропускается молча. Нет данных для проверки конкретного критерия → пометить «нет данных» с указанием, каких именно данных не хватает.
3. Вывод — всегда трёхсостоятельный, одной строкой в контекст (не отдельный файл-отчёт, как и секция «Здоровье»):
   - хотя бы один критерий сработал → явный пункт в обсуждение: метод, наблюдение (что именно случилось), период, источник наблюдения;
   - ничего не сработало, но по части строк «нет данных» → «Реестр методов стиля: подтверждено актуальным N из M; без данных — <методы>: каких данных не хватает» — ложное «всё в порядке» при неполном покрытии запрещено;
   - ничего не сработало, данных хватило на все строки → «Реестр методов стиля: ничего не устарело (проверены все M)».
4. Проверка должна быть видна пилоту даже при результате «всё в порядке», а не молча пропущена.

**Периодичность (уточнено 12.08 по критике Codex):** обход выполняется на сессиях стратегирования в discovery-режиме (шаг 3.2) — это условный, не гарантированно еженедельный ритм: если сессии недели не было, проверки не было. Гарантированный еженедельный обход — отдельное решение пилота (часть живой приёмки РП-513).

**Инвариант:**
- Реестр (`lifestyle-methods-registry.md`) = SoT по статусу практик пилота. Определения практик (can-do) — в PACK-personal (PD.CAT.002, PD.CAT.006); эта секция их не трогает, только читает статусы.
- Эта секция — единственная регулярная точка сверки реестра, помимо случая, когда пилот сам просит открыть файл.
