# Strategy Session — секция методов стиля (РП-513)

## Секция «Методы стиля (РП-513)» в discovery-контекст

**Когда выполнять:** тот же шаг, что секция «Здоровье» (`strategy-session.after.health.md`) — Шаг 3.2 (режим discovery, «состояние пилота изменилось»/первый месяц), перед `/discovery-session`, как один из входных фактов о состоянии пилота.

**Автовызов не подключён** (тот же статус, что у `strategy-session.after.health.md`, Extensions Gate 25.07): SKILL.md `strategy-session` пока не читает `load-extensions.sh strategy-session after` — это платформенный (L1) файл, правится только через `update.sh`/автора (`author_mode`).

До промоции — Стратег читает этот файл вручную на шаге 3.2 и выполняет действие ниже сам.

**Что сделать:**

1. Прочитать `DS-my-strategy/docs/lifestyle-methods-registry.md`.
2. Пройти колонку «Критерий пересмотра (черновик)» — для каждой строки со статусом «в работе»/«сделано (стиль)» проверить, не сработал ли критерий, по фактам сессии/недели (не гадать: нет данных для проверки конкретного критерия → пометить «нет данных», не пропускать молча).
3. Хотя бы один критерий сработал → вывести это явным пунктом в обсуждение (не отдельный файл-отчёт — как и секция «Здоровье», это входные данные для дискуссии, не артефакт).
4. Ничего не сработало → одна строка в контекст: «Реестр методов стиля: ничего не устарело» — проверка должна быть видна пилоту, даже когда результат «всё в порядке», а не молча пропущена.

**Инвариант:**
- Реестр (`lifestyle-methods-registry.md`) = SoT по статусу практик пилота. Определения практик (can-do) — в PACK-personal (PD.CAT.002, PD.CAT.006); эта секция их не трогает, только читает статусы.
- Эта секция — единственная регулярная точка сверки реестра, помимо случая, когда пилот сам просит открыть файл.
