# Day Open — вчерашнее здоровье в чат (РП-469, добавлено 12.09.2026)

**Когда выполнять:** после шага 6 (Вчера), до записи DayPlan (шаг 7) — тот же порядок, что у старого `day-open.summary-extra.sh`, который этот файл заменяет (пир-сессия Claude+Kimi+Codex, 12.09.2026: старый хук писал в `~/Library/IWE/health-data/day-summaries/`, но ничего это никогда не читало — подтверждено grep по всему репозиторию, файл удалён вместе с этой заменой).

**Что сделать:**

```bash
(cd "$HOME/IWE/DS-my-strategy" && python3 -m scripts.lib.health.owner summary \
  --metrics sleep_duration,resting_heart_rate,readiness_score,sleep_score,nightly_hrv \
  --since "$YDAY" --until "$YDAY")
```

`$YDAY` — та же вчерашняя дата, что использует шаг 6 (`YYYY-MM-DD`).

**Что сделать с выводом:** прочитать построчно, сказать пилоту в ответе чата человеческим языком (без технических имён метрик — «индекс восстановления», не `readiness_score`; см. `feedback_response_clarity_for_pilot.md`). Один день почти всегда даёт `0/1` или `1/1` покрытие — это нормально, не ошибка.

**Запрещено (резидентность WP-469, БЛОКИРУЮЩЕЕ):** вставлять эти числа в `DayPlan {date}.md` — ни в переменную шага 7, ни в текст, который туда пойдёт. Значения — только в тексте ответа пилоту. `day-open.checks.md` проверяет итоговый DayPlan скриптом `health-residency-guard.sh` и блокирует коммит при находке.

**Источник недоступен** (`denied`/пустой вывод, оба источника `status: unavailable`) → сказать пилоту честно «данные здоровья сейчас недоступны» одной строкой, не пропускать молча и не выдумывать значение.
