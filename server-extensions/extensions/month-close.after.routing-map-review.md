# Month Close — после основного алгоритма

## Шаг B1. Глубокая ревизия карты маршрутизации знаний (DP.KR.001)

**Когда выполнять:** после шага 9 (Extension point month-close after), перед шагом 10 (запись `MonthClose YYYY-MM.md`).

**Зачем:** еженедельная сверка (`week-close.after.routing-map-check.md`) ловит только новые типы контента. Раз в месяц нужна более глубокая проверка: устарели ли существующие строки §5.2-§5.8, закрылись ли пункты §8 «Известные пробелы», не разошёлся ли `memory/routing-vocab.md` (L0-проекция) с самой картой.

**Что сделать (~15 мин):**

1. Перечитать `PACK-digital-platform/pack/digital-platform/02-domain-entities/DP.KR.001-knowledge-routing.md` §8 «Известные пробелы» целиком — по каждому пункту решить: закрыт / актуален / устарел (репо переименован, практика изменилась).
2. Перечитать §5.2-§5.8 целиком — не только «чего не хватает», но и «что устарело» (путь больше не существует, репо архивирован/переименован).
3. Сверить `memory/routing-vocab.md` (L0 fast-path) с §5.2-§5.8 карты — расхождение допустимо только временно (карта — source-of-truth, routing-vocab — производная проекция); если расхождение старше 1 месяца — завести задачу синхронизации.
4. Обновить `status`/`epistemic_stage` карты по факту ревизии; добавить запись в §9 с датой.
5. Если правок не было — тоже зафиксировать факт ревизии: запись в §9 «Проверено: YYYY-MM-DD, без изменений».

**Не дублирует Routing Gate (DP.SC.036):** тот — point-lookup для одного файла в момент записи. Этот шаг — ежемесячный batch-аудит карты целиком.
