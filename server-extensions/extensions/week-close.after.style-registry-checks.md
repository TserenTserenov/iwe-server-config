# Week Close — после основного алгоритма

## Шаг: Проверки реестра понятий и родов

**Когда выполнять:** вместе с шагом 7 (платформенные шаги), рядом с отчётом свежести каталога реестров.

**Зачем:** реестр понятий и родов (PACK-digital-platform) читает детектор правила A14, а детектор работает с его копией. Копия может разойтись с реестром, ссылка на FPF может устареть после обновления копии FPF, новый реестр в любом репозитории может остаться вне каталога реестров. Раньше такие расхождения замечали случайно.

```bash
bash ~/IWE/scripts/style-registry-weekly-check.sh
```

Вывод идёт в секцию «Платформенные шаги» WeekReport. Четыре проверки блокирующие (копия, ссылки на FPF, тесты, каталог реестров): если одна упала, назвать её в «Требует внимания» и завести фазу в РП-388. Раздел «Журнал детектора» и «Реестр» — информативные.

**Что делать с отчётом:**
- В разделе «Уточнения названий РП за семь дней» показать проверенные названия и число успешных проверок каждого. Проверка может предшествовать созданию карточки и может повториться. Для старых записей сохранилось только первое слово: перед предложением словарной формы запросить у пилота пример. Если журнал недоступен, в отчёт входит предупреждение, остальные проверки продолжаются. Форму и значение для реестра утверждает пилот.
- Повторяющиеся неоднозначные слова → решить, к какому роду их отнести (при сомнении оставить «неоднозначно», записав вопрос-уточнение).
- Строки реестра в статусе draft → предъявить пилоту на подтверждение, не повышать статус без его слова.
- Повторный замер A14 назначается событием из шага «Состояние стражей стиля» ниже (строка «ПОРА»), не датой. Блокировка A14 для Kimi и Codex выключена с 24.11.2026 (решение пилота) и возвращается только после точности не ниже 0,7 на новых срабатываниях; для Claude блокировки A14 нет.
- Раз в месяц и после обновления копии FPF — повторить приёмку: `python3 ~/IWE/scripts/a14-acceptance.py run`, затем `blind` и оценка (шаги в скрипте).

## Шаг: Состояние стражей стиля (РП-388, Ф26/Ф31/Ф36/Ф39)

**Зачем:** проверка стиля Kimi исчезла из настроек (или не стояла) и месяц никто этого не видел, а просроченные замеры 06.11 и 08.11 тоже лежали без движения. Скрипт сверяет, что записано в настройках каждого агента, с тем, что реально запускалось, и сам считает цифры недели.

**Когда выполнять:** на каждом компьютере, где работают агенты (цех и Мак), потому что журналы и настройки у каждого свои. Вывод идёт в секцию «Платформенные шаги» WeekReport с названием компьютера.

```bash
python3 ~/IWE/scripts/style-weekly-state.py
```

Скрипт только читает; настройки, хуки и журналы не меняет. Код возврата 1 = есть тревога.

**Что делать с отчётом:**
- «ТРЕВОГА: … не подключена» или «… не запускалась» → назвать в «Требует внимания» и поставить вопрос пилоту; восстановление настроек агента — только по его слову (S-33).
- Строка «ПОРА» в разделе повторного замера A14 → завести фазу в РП-388: разметка срабатываний двумя слепыми оценщиками, решение о блокировке для Kimi и Codex.
- Числа недели записать в WeekReport строкой «было → стало»; рост доли непояснённых имён вдвое против прошлой недели → пункт в «Требует внимания».
- Пороги (20 срабатываний, неделя в сравнении) — предложение автора скрипта; менять аргументами `--a14-need` и `--days` по слову пилота.
