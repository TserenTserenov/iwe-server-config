# Week Close — после основного алгоритма

## Шаг: Проверки реестра понятий и родов

**Когда выполнять:** вместе с шагом 7 (платформенные шаги), рядом с отчётом свежести каталога реестров.

**Зачем:** реестр понятий и родов (PACK-digital-platform) читает детектор правила A14, а детектор работает с его копией. Копия может разойтись с реестром, ссылка на FPF может устареть после обновления копии FPF, новый реестр в любом репозитории может остаться вне каталога реестров. Раньше такие расхождения замечали случайно.

```bash
bash ~/IWE/scripts/style-registry-weekly-check.sh
```

Вывод идёт в секцию «Платформенные шаги» WeekReport. Четыре проверки блокирующие (копия, ссылки на FPF, тесты, каталог реестров): если одна упала, назвать её в «Требует внимания» и завести фазу в РП-388. Раздел «Журнал детектора» и «Реестр» — информативные.

**Что делать с отчётом:**
- Повторяющиеся неоднозначные слова → решить, к какому роду их отнести (при сомнении оставить «неоднозначно», записав вопрос-уточнение).
- Строки реестра в статусе draft → предъявить пилоту на подтверждение, не повышать статус без его слова.
- Точность A14 по журналу ≥ 0,7 и не меньше трёх срабатываний → поставить вопрос о блокирующем режиме для Claude (сейчас он на предупреждении; Kimi и Codex блокируют).
- Раз в месяц и после обновления копии FPF — повторить приёмку: `python3 ~/IWE/scripts/a14-acceptance.py run`, затем `blind` и оценка (шаги в скрипте).

## Откат

Удалить или переименовать этот файл — Week Close вернётся к прежнему поведению.
