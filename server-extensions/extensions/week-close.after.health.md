# Week Close — локальные данные здоровья (РП-470)

## Часть A. Указатель на локальные health-данные в WeekReport (БЛОКИРУЮЩЕЕ)

**Когда выполнять:** шаг 9 (Extensions after) SKILL week-close — после шага 8 (запись итогов в WeekReport), до шага 11 (коммит).

**Резидентность (WP-469, исправление 22.08):** WeekReport коммитится и пушится в Git. Поэтому числовые показатели сна, пульса и плавания в него не записываются. Источник остаётся локально; недельный срез пересчитывается по запросу. В WeekReport допустима только строка-указатель без health-значений.

**Что сделать (часть A и часть B — одним вызовом shell, не двумя отдельными: значения переменных ниже не переживут границу между отдельными вызовами Bash-инструмента, найдено холодным ревью 12.09.2026):**

```bash
# WEEK_START/WEEK_END — понедельник..воскресенье закрываемой недели (не текущей даты)
WEEK_START="YYYY-MM-DD"
WEEK_END="YYYY-MM-DD"
REPORT_FILE="$HOME/IWE/DS-my-strategy/current/WeekReport W{N} YYYY-MM-DD.md"

if grep -q "^_Здоровье (РП-470):" "$REPORT_FILE"; then
  echo "week-close.after.health: указатель уже присутствует — пропуск (idempotent)"
else
  bash "$HOME/IWE/extensions/week-close.summary-extra.sh" "$WEEK_START" "$WEEK_END" >> "$REPORT_FILE"
fi

bash "$HOME/IWE/DS-my-strategy/scripts/health-residency-guard.sh" "$REPORT_FILE" || exit 1

# Часть B ниже, та же переменная WEEK_START/WEEK_END — тренд пилоту в чат, не в файл.
(cd "$HOME/IWE/DS-my-strategy" && python3 -m scripts.lib.health.owner trend \
  --metrics sleep_duration,resting_heart_rate,readiness_score,sleep_score,nightly_hrv,steps,active_minutes \
  --since "$WEEK_START" --until "$WEEK_END")
```

**Часть A — инвариант:**
- В WeekReport — только строка-указатель без значений; проверка выше (обобщена 12.09.2026, пир-сессия Claude+Kimi+Codex — та же замена узкой регулярки на `health-residency-guard.sh`, что и в `day-open.checks.md`) блокирует коммит при любом найденном значении.
- Данных нет → скрипт пишет честную value-free заглушку, тихий пропуск запрещён.
- Скрипт author-only, в FMT-exocortex-template не поставляется.

**Часть B (добавлено 12.09.2026) — почему нужна отдельно от указателя A:** до 22.08 WeekReport показывал реальные числа и это оказалось утечкой резидентности (см. карточку WP-470); фикс убрал числа отовсюду, а не только из git-файла — с этой даты пилот вообще не видел тренд здоровья на закрытии недели. Часть B возвращает видимость через узел-владелец (`scripts/lib/health/owner.py`, WP-469 Ф6, собран 12.09.2026 пир-сессией), с мандатом и журналом выдачи, не через прямой SQL.

**Что сделать с выводом части B:** прочитать построчно (`metric: было -> стало (направление)`), пересказать пилоту в ответе чата человеческим языком (см. `feedback_response_clarity_for_pilot.md` — без технических имён метрик, с расшифровкой «индекс восстановления = насколько тело готово к нагрузке» и т.п. при первом упоминании). **Запрещено:** копировать эти числа в `WeekReport W{N}.md`, в файл этой сессии Week Close или в любой другой git-tracked артефакт — только в текст ответа пилоту. Источник недоступен (`denied`/пустой вывод) → сказать честно «данные здоровья сейчас недоступны», не выдумывать тренд.

**Проверка перед коммитом:** `health-residency-guard.sh` в блоке выше уже вернул ✅/exit 0 для `$REPORT_FILE` — при exit 2 команда `|| exit 1` уже остановила выполнение раньше, до части B. Дополнительно (тем же вызовом, если нужна отдельная сверка count):

```bash
grep -c "^_Здоровье (РП-470):" "$REPORT_FILE"   # ровно 1
```

**Не встроено:** привязка к стоп-листу «перегрузка/выгорание». Если она понадобится, потребитель должен читать через узел-владелец, не Git-отчёт.
