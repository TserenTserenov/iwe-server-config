# Month Close — секция здоровья (РП-470)

## Шаг A3. Секция «Здоровье (РП-470)» в MonthClose (БЛОКИРУЮЩЕЕ при наличии базы)

**Когда выполнять:** ПОСЛЕ шага 10 (Запись `archive/MonthClose YYYY-MM.md`), ДО шага 11 (Коммит) — рядом с шагом A1 (multiplier-trend).

**Дизайн (решение пилота 2026-07-18, чат):** вид «недели + тренд», три метрики
(сон, пульс покоя, плавание — те же, что в Day Open и WeekPlan), обязательный маркер
покрытия («N из D дней»). Точка потребления — только MonthClose; стоп-листы
стратсессии этот срез не читают (отдельный вопрос, не активирован).

**Что сделать:**

```bash
# MONTH — ЗАКРЫВАЕМЫЙ период (шаг 1a), НЕ текущий месяц: Month Close запускается
# в первый Пн следующего месяца и закрывает прошлый.
MONTH="YYYY-MM"  # из шага 1a
REPORT_FILE="$HOME/IWE/DS-my-strategy/archive/MonthClose $MONTH.md"

# Идемпотентность: секция уже есть (повторный прогон) — не дублировать.
if grep -q "## Здоровье (РП-470)" "$REPORT_FILE"; then
  echo "month-close.after.health: секция уже присутствует — пропуск (idempotent)"
else
  bash "$HOME/IWE/extensions/month-close.summary-extra.sh" "$MONTH" >> "$REPORT_FILE"
fi
```

**Инвариант:**
- Данных нет → скрипт сам пишет честную заглушку («нет данных за YYYY-MM»), секция всё равно присутствует — тихий пропуск запрещён (тот же принцип, что в Day Open).
- Вывод скрипта детерминированный (SQLite), LLM его не переписывает — как health-строка в Day Open.
- Скрипт author-only (личные данные), в FMT-exocortex-template не поставляется — L1 вызывает его только через этот extension-файл.

**Проверка перед коммитом:** `grep -c "Здоровье (РП-470)" "$REPORT_FILE"` → ровно 1 (секция есть, не продублирована). Если 0 — шаг не выполнен, коммит отложить.
