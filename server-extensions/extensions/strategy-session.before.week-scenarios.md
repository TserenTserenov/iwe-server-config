# Сессия стратегирования: сценарии недели

> Авторское расширение (WP-518 Ф23, формат v2.1, пир-сессия `2026-11-13-12-wp518-week-scenarios-format`, решение пилота 13.11.2026: делать в личном слое, в шаблон IWE — после тестирования и после выпуска 0.42; правка по замечаниям Kimi и проверке Fable — пир-сессия `2026-11-13-17-wp518-wp561-scenario-check`). Единица приоритета недели — сценарий (проверяемый результат), РП остаётся носителем часов.

**Главное правило.** Текст сценария — имя, описание, проверку, критерий — формулирует пилот. Ты свой вариант не предлагаешь, не дописываешь и не сокращаешь: переносишь слова пилота в карточку и показываешь блок дословно. Молчание, «ок», «давай» на пересказ — не утверждение; утверждение — пилот прислал текст сам или ответил «да» на показанный дословно блок из его слов.

**Этап 8 «План недели: кандидаты».** После состава пула предложи пилоту сценарии недели отдельным вопросом этого же этапа (одна остановка на этап сохраняется):

1. **Кандидаты.** Сценарии с блоков в карточках РП пула и перенесённые с прошлой недели (тот же номер). Блок у владельца — в разделе `## Сценарии` карточки (не внутри фазы: закрытые фазы уезжают в архив и обрывают ссылку из плана):
   ```
   <a id="SC-<РП>-NN"></a>
   ### SC-<РП>-NN — <имя, до 60 знаков>
   <описание — одна строка>
   - **Проверка:** <до 80 знаков>
   - **Критерий:** <одна строка>
   ```
   Описание сценария пишется только у владельца; в план недели — только ссылка и копия проверки. Номер — следующий свободный `NN` в этой карточке; номер не меняется никогда.
2. **Перенесённый сценарий** покажи строкой «перенесён, статус на сейчас: …» и спроси: оставить, переформулировать или снять. Без ответа не переноси. Переформулировать = новый номер с новым текстом пилота (по п.3); старый номер снимается, его блок не правится — к старому номеру относятся прежние проверки.
3. **РП пула без сценария.** Сначала одним списком спроси, по каким РП пула нужны сценарии; остальные получают «нет проверяемого результата» — это не мешает утверждению. По каждому нужному попроси пилота сформулировать четыре строки: имя (до 60 знаков), описание (одна строка), проверку (до 80 знаков), критерий (одна строка). Длиннее предела — назови длину и попроси сократить. Пилот ответил не на все четыре — блок не пиши, РП остаётся без сценария, скажи об этом. Блок пишется только в существующую карточку-владельца, новых документов не создавай. Известный запрет на 13.11: в РП-581 пилот запретил новые документы до согласия Андрея — сценарий туда не пиши, спроси, где записать. Иной запрет в карточке РП — тоже спроси.
4. **Список.** Покажи кандидатов таблицей, одна строка на сценарий: номер, имя, проверка, РП-носитель, статус на сейчас. Статус нового сценария — «не начат»; другой статус — только со слов пилота и со ссылкой на свидетельство. Порядок — твоё предложение, так и подпиши; порядок и состав решает пилот. Без его ответа во frontmatter плана ничего не пиши.

**Перед этапом 10 «Утверждение».** Запиши утверждённый пилотом список во frontmatter плана недели, `scenarios:` по порядку пилота:

```yaml
scenarios:
  - id: SC-608-01
    owner_ref: "inbox/WP-608/WP-608.md#SC-608-01"   # путь от корня DS-my-strategy
    wp: 608                                         # число, без кавычек
    check: "<дословная копия поля «Проверка» владельца>"
    status_at_open: not_started                     # not_started | in_progress | passed | failed
    as_of: {date: 2026-11-16, last_event: null}     # дата без кавычек; last_event — null, пока нет событий проверки
    evidence: null                                  # при passed/failed — адрес http(s) или путь к существующему файлу
```

Таблицу собери скриптом, руками не пиши:

```bash
python3 scripts/lib/week_scenarios.py render "<путь к плану недели>" --write
python3 scripts/lib/week_scenarios.py check  "<путь к плану недели>"
```

Проверка утверждения (`strategy-session-checks-runner.sh`) повторяет эту проверку. С недели 16.11.2026 план без `scenarios:` не проходит утверждение. Если пилот решил провести неделю без сценариев — `scenarios: []` и `scenarios_waiver:` с его словами дословно; сам за пилота это поле не заполняй. Планы до 16.11 проверка пропускает с пометкой. Строка «нет проверяемого результата» в выводе — для раздела «Требует внимания», не ошибка.

Статус в файле плана — снимок на момент утверждения. В течение недели план не правится ради статуса: текущий статус покажет табло дня (РП-561 Ф53, запись решения DR-07), когда появится событие проверки сценария.
