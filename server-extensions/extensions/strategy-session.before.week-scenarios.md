# Сессия стратегирования: сценарии недели

> Авторское расширение (WP-518 Ф23, формат v2.1, пир-сессия `2026-11-13-12-wp518-week-scenarios-format`, решение пилота 13.11.2026: делать в личном слое, в шаблон IWE — после тестирования и после выпуска 0.42). Единица приоритета недели — сценарий (проверяемый результат), РП остаётся носителем часов.

**Этап 8 «План недели: кандидаты».** После состава пула предложи пилоту сценарии недели отдельным вопросом этого же этапа (одна остановка на этап сохраняется):

1. Кандидаты — сценарии с канонических блоков в карточках РП пула и перенесённые с прошлой недели (тот же номер). Блок у владельца: строка-якорь `<a id="SC-<РП>-NN"></a>`, под ней заголовок `### SC-<РП>-NN — <имя>` (имя ≤60), строка описания, поля `- **Проверка:**` (≤80) и `- **Критерий:**`. Описание сценария пишется только у владельца; в план недели — только ссылка и копия краткой проверки.
2. У РП пула нет описанного сценария → не выдумывай описание сам: назови пилоту «нет проверяемого результата» и спроси, нужен ли сценарий. Новое описание пишется в карточку-владельца только после того, как пилот утвердил его текст, и не в РП, где пилот запретил новые документы (на 13.11 — РП-581 до согласия Андрея).
3. Покажи пилоту список по порядку важности: номер, имя, краткая проверка, РП-носитель, статус на сейчас. Порядок и состав решает пилот; без его ответа во frontmatter плана ничего не пиши.

**Перед этапом 10 «Утверждение».** Запиши утверждённый пилотом список во frontmatter плана недели (`scenarios:`: `id`, `owner_ref` = `<путь>#<id>`, `wp`, `check` — дословная копия поля владельца, `status_at_open` из `not_started | in_progress | passed | failed`, `as_of: {date, last_event}`, `evidence` — обязателен при `passed`/`failed`). Таблицу собери скриптом, руками не пиши:

```bash
python3 scripts/lib/week_scenarios.py render "<путь к плану недели>" --write
python3 scripts/lib/week_scenarios.py check  "<путь к плану недели>"
```

Проверка утверждения (`strategy-session-checks-runner.sh`) повторяет эту проверку. С недели 16.11.2026 план без `scenarios:` не проходит утверждение. Если пилот решил провести неделю без сценариев — `scenarios: []` и `scenarios_waiver:` с его словами дословно; сам за пилота это поле не заполняй. Планы до 16.11 проверка пропускает с пометкой. Строка «нет проверяемого результата» в выводе — для раздела «Требует внимания», не ошибка.

Статус в файле плана — снимок на момент утверждения. В течение недели план не правится ради статуса: текущий статус покажет динамический план дня (РП-561 Ф53), когда появится событие проверки сценария.
