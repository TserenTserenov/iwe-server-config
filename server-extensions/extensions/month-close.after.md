# Month Close — после основного алгоритма

## Шаг A1. Append в трекер мультипликатора (БЛОКИРУЮЩЕЕ)

**Когда выполнять:** ПОСЛЕ шага 10 (Запись MonthClose YYYY-MM.md), ДО шага 11 (Коммит).

**Что сделать:**

1. Открыть `DS-my-strategy/archive/multiplier-trend.md`
2. Добавить новую строку в таблицу «История» (НЕ перезаписывать существующие):

```markdown
| YYYY-MM | {WakaTime} | {бюджет} | **{N.Nx}** | {фаза} | {калибр} | {N из M} (список ✅ R) | {ТОС / комментарий} |
```

3. Источник данных — только что записанный `MonthClose YYYY-MM.md` § Обзор.
4. Файл `multiplier-trend.md` — append-only исторический ряд для следующего Strategy Session первой сессии месяца (вход стадии 2 каскада ВДВ v9).

**Зачем:** закрытие цикла обратной связи Month Close → Strategy Session. Без этого шага мультипликатор апреля недоступен на сессии в мае для оценки динамики. См. WP-196 Ф13.

## Шаг A1.5. Пересборка контракта стратегического контекста (WP-149 Ф1)

**Когда выполнять:** ПОСЛЕ шага A1 (стратегические источники месяца финализированы), ДО коммита.

```bash
python3 ~/IWE/DS-my-strategy/scripts/build-strategic-context.py
git -C ~/IWE/DS-my-strategy add machine/strategic-context.yaml
```

Скрипт собирает `machine/strategic-context.yaml` (цели R месяца, топ-НЭП, ТОС недели, привязки РП→R, активные проекты) для рендера персонального руководства. Exit 1 = какая-то секция не собралась (`missing` непуст) — файл всё равно записан, но источники надо починить и перезапустить. Также запускать на Strategy Session при смене фокуса месяца.

## Шаг A2. Подсказка пользователю про следующую Strategy Session

После всех шагов закрытия — добавить в финальный отчёт строку:

> **Следующее действие:** Strategy Session (первая в месяце) — на ней Стратег прочитает `MonthClose YYYY-MM.md` + `multiplier-trend.md` и пересмотрит фокус. См. SKILL strategy-session-weekly шаг 0.

Это служит маркером цикла: данные не лежат мёртвым грузом, они — вход следующей стадии.
