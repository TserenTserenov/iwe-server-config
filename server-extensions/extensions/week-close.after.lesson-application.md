# Week Close Extension (after) — Применение lesson недели

> **Источник:** WP-364 Развилка 1 РЕШЕНО (peer-сессия [2026-05-29-23-wp-364-daily-fork](../DS-my-strategy/sessions/2026-05/2026-05-29-23-wp-364-daily-fork/report.md)).
>
> **Принцип:** lesson в `personal-guide/guide/YYYY-MM-DD.md` собирается под рабочие задачи пилота. Проверка обучения = наблюдение применения в рабочих репо. Без этого шага lesson превращается в декоративный артефакт «прочитал и забыл».

## Шаг: Чеклист «Применение lesson недели»

Выполнить **после** основных шагов Week Close (ретро + carry-over), **до** платформенных шагов (бэкап, dirty repos).

### 1. Собрать lesson за неделю

```bash
PERSONAL_GUIDE="$HOME/IWE/personal-guide"
WEEK_START=$(date -v-mon +%Y-%m-%d 2>/dev/null || date -d "last monday" +%Y-%m-%d)
WEEK_END=$(date +%Y-%m-%d)

# Список lesson за неделю (personal-guide/guide/, структура после rename lesson/→guide/, commit fb3c753)
LESSONS=$(find "$PERSONAL_GUIDE/guide" -maxdepth 1 -name "*.md" 2>/dev/null | \
  awk -F/ -v start="$WEEK_START" -v end="$WEEK_END" \
    '{ name=$NF; gsub(/\.md$/, "", name); if (name >= start && name <= end) print }')

echo "Lesson за неделю:"
echo "$LESSONS"
```

### 2. Для каждой lesson — проверка применения

| lesson | bottleneck/тема | связанная задача в WeekPlan | признак применения (где искать) | статус |
|--------|-----------------|----------------------------|---------------------------------|--------|
| YYYY-MM-DD.md | (что изучали) | WP-N / задача | git activity в репо X / артефакт Y | ✅/⚠️/❌ |

**Где искать признаки применения:**
- Новые коммиты в рабочих репо за неделю с упоминанием темы lesson.
- Новые артефакты (документы, скрипты, диаграммы) по теме lesson.
- Новые подходы / методы / различения в работе (отслеживается через captures → memory).

### 3. Итог

- Какой % lesson за неделю применён?
- Если <50% — добавить в Carry-over: «Применить lesson за неделю N: ...».
- Если pattern: lesson часто не применяются → сигнал к ревью content-контракта Портного (lesson слишком теоретичны или не привязаны к актуальным РП).

### 4. Capture

Если обнаружен паттерн (например: lesson по теме X стабильно не применяются → нужно пересмотреть контракт): записать в `memory/feedback_*.md` или `memory/lessons_*.md` через ke-flow.

## Что не входит в этот чеклист

- Автоматизация проверки (grep коммитов по hash'ам lesson) — отдельный РП, не блокер.
- Изменение content-контракта lesson (что Портной включает) — это ответственность WP-149.
- Прерывание lesson, не привязанной к WeekPlan — это ответственность входа Портного (Шаг 1 WP-149, расширение из решения Развилки 1).

## Откат

Если этот шаг занимает >5 мин и не приносит ценности — пометить как «не выполнять до накопления значимой истории lesson». Возвращаться через 4 недели.
