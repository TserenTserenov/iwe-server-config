## Заявка на время пилота (РП-561 Ф55, контракт v3 DR-06)

С 11.11 заявку подаёт само открытие сессии (решение пилота: прежний отдельный
шаг агенты пропускали — за неделю одна настоящая заявка). Агенту остаётся
передать оценку в вызов `session-guard.sh open`.

**Сессия по РП (`WP-N`), пилот участвует** — добавить к `open`:

```bash
--estimate-minutes <оценка>
```

Оценка: если Ритуал согласован — его «Оценка» в минутах (~1.5h → 90); если
Ритуал не нужен (продолжение того же РП) — назвать пилоту свою оценку этой
сессии одной фразой и передать её. Ноль и «на всякий случай» не подставлять.

**Пилот не участвует** (автономный прогон, сессия без пилота) — вместо оценки
`--no-plan-reserve`. Плановые запуски по расписанию заявку не подают сами.

Без обоих флагов `open` по РП печатает предупреждение «Бронь времени пилота не
подана» с командой для подачи — подать её, как только оценка известна.

**Что делает открытие.** Программа брони (`scripts/plan-reserve-on-open.sh`)
сама выбирает канал: приёмник на «Цехе» или ключ канала Мака; нет ни того ни
другого — ничего не подаёт и молчит. Если заявка ушла, а отметка о начале нет,
программа сама досылает отметку. Строку из вывода `open` показать пилоту как
есть:
- «Бронь времени пилота: N мин на WP-N сегодня подана» — всё, больше ничего;
- «⚠️ Бронь … не подана: очередь была занята / нет связи с „Цехом“» — повторить
  напечатанную команду позже в этой сессии;
- «⚠️ … отказ приёмника …» — показать пилоту код отказа, вручную не повторять.

Заявки всех параллельных сессий складываются в дневной бюджет пилота — 1800
минут (600 × 3, решение пилота 11.11). Заявку сверх бюджета отклоняет мост;
отказ виден в сводке дня (закрытие дня) и в журнале плана.
