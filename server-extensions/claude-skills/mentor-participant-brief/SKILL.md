# /mentor-participant-brief

> **Scope:** по нику или имени человека собрать для наставника сводку обо всём известном и подготовить черновик ответа (обещание DP.SC.206, РП-613 Ф1).
> **Not in scope:** отправка ответа человеку (отправляет наставник), правка данных и самого инструмента, построение табло одного человека без просьбы.
> **Role:** помощник наставника (MIM.R.001 исполняет человек, помощник готовит материал).

## When to use

- Наставник присылает ник, имя или сообщение участника потока S1/S2 или консультации и хочет ответить с полной картиной.
- Наставник просит «что известно об этом человеке» или «подготовь ответ».
- Наставник просит показать табло: сначала сводка, табло по правилу ниже.

## Preconditions

1. **WP Gate precondition.** Работа идёт внутри РП-613 «Ответы участникам сообщества». Сессию РП открывает наставник по порядку из карточки, скилл его не заменяет.
2. **Допуск.** Живые данные возвращаются только допущенному наставнику потока. Отказ инструмента («вызывающий не наставник…») — не повод искать обход: сообщить наставнику и остановиться.

## Algorithm

### Step 1 — Найти человека

Input: ник, имя или фрагмент сообщения от наставника.
Action: актуальные коды потоков взять из карточки РП-613 (раздел «Рабочий порядок», проверить на странице «Мои активные потоки» в личном кабинете, если код мог смениться). Вызвать табло потока (`mentorship_get_stream_overview`) по обоим потокам; имена получить через `mentorship_resolve_participant_names`. Не нашёлся в потоках — искать по содержанию сообщений, затем по упоминаниям вне бота, затем спросить наставника.
Output: один идентификатор участника и код потока, либо список кандидатов. Несколько совпадений — вопрос наставнику, личности не склеивать.

### Step 2 — Собрать сводку

Input: идентификатор участника и код потока.
Action: вызвать карточку участника (`mentorship_get_participant_card`). Выписать по источникам: переписка и прежние заметки, ступень и квалификация, характеристики, активность, баллы, чек-лист, прежние потоки и консультации. Для каждой части — источник и свежесть. Нет данных или нет допуска — так и написать, не выдавать за «активности нет». Вывод помощника помечать как вывод, рядом исходный факт.
Правило источника (найдено 27.10.2026 на живой сводке): у каждой цифры называть, откуда она. Карточка участника баллов не отдаёт — число баллов или «последнее начисление» без источника не писать, а сказать «баллов в карточке нет, смотреть в учёте баллов»; если баллы пришли из другого места (табло, учёт), назвать это место. Ноль баллов при высокой активности — повод для вопроса владельцу учёта баллов (РП-567), а не вывод о человеке. Когда карточка и табло расходятся (ступень, чек-лист), показать оба значения и источник каждого, не выбирать молча.
Output: сводка в чате: 5-8 строк, затем пробелы и недоступные источники одной строкой.

### Step 3 — Предложить черновик ответа

Input: сводка и последнее сообщение человека.
Action: написать черновик ответа в стиле наставника, с опорой на сводку и методику (материалы практикума в репозитории Programs, путь в карточке РП-613). Предложить наставнику правку или утверждение.
Output: черновик, ждущий решения наставника. Автоматически не отправлять.

### Step 4 — Сохранить отправленное

Input: текст, который наставник реально отправил.
Action: сохранить его заметкой (`mentorship_add_participant_note`). Если ответ ушёл не через бота — пометить `sourceHint: mentor_reply_sent_outside_telegram`.
Output: заметка в карточке участника.

### Step 5 — Табло (только если спросили)

Input: просьба наставника «покажи табло».
Action: по умолчанию дать ссылку на табло потока из карточки РП-613 и напомнить об известном баге подмены потока (после смены кода нажать Tab перед загрузкой). Табло одного человека собирать только по явной просьбе (решение пилота 27.10.2026).
Output: ссылка либо собранное табло.

## Bundled resources

- Нет. Источники порядка работы: карточка РП-613, обещание DP.SC.206 в PACK-digital-platform.

## Anti-patterns

- Склеивать личности или угадывать участника при нескольких совпадениях.
- Выдавать отсутствие данных за отсутствие активности.
- Пересказывать историю человека в файл: история одна, в сервисе наставничества.
- Чинить найденный дефект данных на месте: чек-лист — РП-522, имена — РП-427, характеристики — РП-151, инструмент — РП-578.
- Отправлять ответ без утверждения наставника.
