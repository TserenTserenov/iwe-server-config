# Загрузка принципов

Запрос: $ARGUMENTS

## When to use

Загрузка применимых принципов для задачи из иерархии Pack → SPF → FPF. Используй когда нужно найти релевантные принципы перед принятием решения.

## Fallback Chain

```
Pack (предметное) → SPF (корректность) → FPF (первые принципы)
```

## Режимы (определи по контексту запроса)

| Режим | Триггер | Что делать |
|-------|---------|-----------|
| **lookup** | Запрос содержит код паттерна (A.7, B.5, F.18) или конкретный термин | Grep по FPF → точная секция. Объясни в engineering-языке (см. `memory/fpf-reference.md` § Трансляция) |
| **review** | «Проверь», «сверь с FPF», артефакт для проверки | Загрузи артефакт + релевантные принципы → сверка пункт за пунктом → findings |
| **design** | «Спроектируй», «как сделать по FPF», задача проектирования | Подбери применимые паттерны (A.1 границы, A.6 состав, A.7 различения, B.5 ADI) → конкретные рекомендации |
| **characterize** | «Сравни», «оцени варианты», «как выбрать» | A.17-A.19 (Lawful Comparison): критерии → индикаторы → оценка вариантов по одинаковой шкале |
| **teach** | «объясни FPF», «что такое FPF», «с нуля», «введение» | Дай обзор FPF: что это, зачем, ключевые блоки (различения, паттерны, первые принципы) → объясни в engineering-языке без жаргона |
| **diagnose** | «какие принципы нарушаю», «что не так», «найди проблему», «проверь мою работу» | Получи описание работы/решения → найди расхождения с принципами FPF/Pack → назови конкретные нарушения с указанием принципа и где именно |
| **prioritize** | «наиболее важны», «для роли», «в роли», «для меня как» | Определи роль из аргумента → найди принципы FPF/Pack, релевантные этой роли → ранжируй по применимости → объясни почему каждый важен именно для этой роли |

**БЛОКИРУЮЩЕЕ — полный каталог, не выжимка.** Пилот зафиксировал жалобу пользователя (13.08.2026): «Пользователь жалуется на то, что когда он говорит с опорой на FPF, то ты не полностью читаешь весь FPF, правильно?». Расплывчатая формулировка запроса («с опорой на FPF», «по FPF») не отменяет полноты поиска — она НЕ повод ограничиться `memory/fpf-reference.md` (короткой выжимкой на ~25 паттернов) вместо полного текста `FPF-Spec.md` (294 тела паттернов). Если запрос называет опору на FPF без конкретного кода паттерна — не занижай до режима `teach`/`lookup` по короткой памяти: выполняй Algorithm §3-4 целиком (поиск по всему источнику), а память используй только для перевода терминов на выходе (см. No-Jargon ниже), не как замену поиску.

**Карточки паттернов (WP-525 Ф1, доставлено Ф2 19.08.2026).** `memory/fpf-reference.md` — тонкий индекс (манифест), не источник детального разбора: развёрнутые разборы паттернов, прошедших критерий отбора, живут отдельными файлами `memory/fpf-cards/<код>.md`. Если для ответа нужен конкретный код паттерна из манифеста — грузи явно нужную карточку по коду (Read), не более 1-2 карточек за одно обращение к скиллу; индекс манифеста автогенерируется из карточек, руками не редактировать. Это правило про режимы `lookup`/`review`/`design` с известным кодом паттерна — при полном поиске по «БЛОКИРУЮЩЕЕ — полный каталог» выше карточки не участвуют вовсе, источник там `FPF-Spec.md`.

**БЛОКИРУЮЩЕЕ — логирование обращения к карточке (WP-549, MVP).** Каждый раз, когда этот скилл грузит конкретную карточку по коду (шаг выше) — допиши одну строку JSON в `memory/fpf-usage.log` (создать файл, если его нет; директория `memory/` уже существует). Не пропускать этот шаг «по инерции» выполнения Algorithm §5 — см. явный под-шаг там. Время — командой `date -u +%Y-%m-%dT%H:%M:%SZ`, не приблизительно:
```json
{"ts": "<вывод date -u +%Y-%m-%dT%H:%M:%SZ>", "code": "<код карточки>", "event": "read", "source": "fpf_cmd", "session": "<id текущей сессии, если известен, иначе omit>", "result": "success"}
```
Сбой записи (диск/права) не блокирует ответ — попытка best-effort, ошибку не показывать пилоту.

**БЛОКИРУЮЩЕЕ — логирование полного поиска по каталогу (WP-566 Ф7, расширение WP-549).** Каждый раз, когда сработал режим «полный каталог» выше (поиск по всему `FPF-Spec.md`, не по карточке из манифеста) — та же строка в `memory/fpf-usage.log`, но `"code": "FULL_SEARCH"`, `"event": "full_search"` вместо `"read"` (остальные поля — как в примере выше). Это чисто локальная запись на этой машине — она НЕ появляется на общем табло обращений (Grafana), пока не будет отдельного конвейера доставки таких локальных записей в общую базу (см. WP-566 Ф7 для контекста и незакрытого хвоста). Единственная цель этой строки сейчас — не потерять факт обращения на будущее, когда такой конвейер появится.

Прямое чтение `FPF/FPF-Spec.md` или карточки в разговоре БЕЗ вызова `/fpf` (например, через `Read`/`grep` напрямую) по-прежнему не логируется — вне периметра этого скилла, осознанное ограничение (см. `inbox/WP-549/WP-549.md`, `inbox/WP-566/WP-566.md` Ф7).

**БЛОКИРУЮЩЕЕ — No-Jargon:** Каждый FPF-термин в output → engineering-эквивалент в скобках или вместо. Без исключений.
- Известные: `memory/fpf-reference.md` § Трансляция (Holon, F-G-R, Alpha, Mereology, Affordance, ADI...)
- Неизвестные (TransformerRole, senseFamily, Γ_*, ReferencePlane и т.п.): перевести по контексту, добавить `(FPF: <оригинал>)`. Не оставлять FPF-термин без перевода.
- **Тест перед выводом:** пробежать output — есть ли термин, непонятный инженеру без FPF? Если да — перевести.

## Algorithm

### 0. Проверь, что читаешь полный текст, а не ссылку

Ссылка на FPF, список имён файлов или обрезанный фрагмент — это ещё не доступ к тексту (правило автора, `FPF/USING-FPF.md`).

Шаг относится к локальной копии `FPF/` в рабочей области; пути ниже даны от её корня (`$IWE_WORKSPACE`), пути с пробелами (`Engineering DPF Suite/...`) бери в кавычки. В браузерной версии, где копии нет, или когда поиск идёт через MCP: читай документ целиком (`knowledge_get_document`) и называй источник.

- Убедись, что есть `FPF/USING-FPF.md`, и прочитай его, если не читал в этой сессии: это общая инструкция автора по поиску и чтению паттернов.
- Назови версию копии: `git -C FPF log -1 --format='%h %ad' --date=short`. Дата коммита копии старше 30 дней или файла `USING-FPF.md` нет → скажи об этом пользователю: копия устарела, обновит `update.sh` (или вручную `git -C FPF pull --ff-only`, если в копии нет своих правок).
- Нет папки `FPF/` или нужного паттерна нет в полном тексте → прямо скажи «доступа к полному тексту нет» и оставь зависимый вывод открытым. Не пересказывай паттерн по памяти.
- Поиск: `rg -n -i -C 2 --no-ignore -g '*.md' -- '<термин по-английски и по-русски>' FPF`. Совпадение в оглавлении или справочнике — не тело паттерна.
- Чтение паттерна целиком по номеру (точку в номере экранируй `\.`): `rg -U --no-heading --no-line-number --no-filename --color never '(?ms)^## <ID> [^\r\n]*\r?\n.*?^### <ID>:End[ \t]*\r?$' -- <файл>`. Вывод обрезан → читай тот же файл по диапазонам строк.
- Нет `rg` (ripgrep) → те же шаги через `grep -rn -i` по файлам `FPF/**/*.md` и чтение диапазонами строк (`sed -n 'A,Bp'`): начало — строка `## <ID> `, конец — `### <ID>:End`.

### 1. Определи режим

По таблице выше. Если неясно — режим lookup.

### 2. Классифицируй источник

- Предметное знание (архитектура, домен, сервис) → source_type=pack
- Форма, процесс, корректность → source=SPF
- Базовые различения, первые принципы → source=FPF

### 3. Ищи через iwe-knowledge

- `iwe-knowledge search(query="<запрос>", source_type="pack")` -- по всем Pack
- `iwe-knowledge search(query="<запрос>", source="SPF")` -- по SPF
- `iwe-knowledge search(query="<запрос>", source="FPF")` -- по FPF
- Если первый уровень не дал результатов -- спускайся по fallback chain

### 4. Если iwe-knowledge недоступен

(нет в `/mcp`):
- Pack: читай файлы `PACK-*/pack/` через Glob + Read
- SPF: читай `SPF/docs/` через Glob + Read
- FPF: читай `FPF/Readme.md` (обзор) или ищи через Grep по `FPF/`

### 5. Покажи результат

Релевантные принципы с пояснением, как они применимы к задаче. Включай ссылку на источник (github_url из результата поиска или путь к файлу). **Переводи FPF-термины** в engineering-язык.

**Источник в конце ответа.** Укажи: какая публикация и версия копии (commit), номера паттернов и разделы, что предполагаешь и чего не хватает для вывода. Дословная цитата нужна только когда проверяется толкование, а не в каждом ответе.

Если на шаге 2-4 грузилась конкретная карточка по коду из `memory/fpf-cards/` — допиши строку в `memory/fpf-usage.log` (формат и БЛОКИРУЮЩЕЕ правило см. выше, до Algorithm) ДО показа результата пилоту, не после.

Если вместо этого сработал режим «полный каталог» (шаг 4, поиск по всему `FPF-Spec.md`) — та же точка, но строка с `"code": "FULL_SEARCH"`, `"event": "full_search"` (формат см. выше, до Algorithm).
