# /pack-subscribe — Подписка на чужой пак

> **Роль:** R6 Кодировщик
> **Триггер:** «подключи пак», «какие паки есть», `/pack-subscribe [имя]`
> **Зеркальный скилл:** `/pack-new` (создание СВОЕГО пака). Подписка не создаёт пак — подключает чужой только для чтения.
> **Обкатка:** S-58 (WP-532), прототип. Гипотеза H-293: подключение ≤1 минуты.
> **0.2 (02.09):** автообновление на старте сессии + самонастраиваемая область поиска по умолчанию (запрос пилота после первого прогона).

## Обещание (контракт)

**Вход:** имя пака из каталога (или пусто — показать витрину).
**Выход:** пак склонирован в `~/IWE/<имя>` только для чтения, помечен в CLAUDE.md пользователя, включён в область поиска, отмечен в реестре репозиториев пользователя; пользователю выдана памятка подписчика.

**Инвариант (БЛОКИРУЮЩИЙ):** подписанный пак никогда не редактируется локально. Единственные операции: `git pull` (обновления) и чтение. Адаптация знания = копия в СВОЙ пак с атрибуцией (источник + версия), оригинал не трогается.

## Алгоритм

### 1. Каталог

Источник каталога, по убыванию приоритета:
1. Локальная копия `~/IWE/pack-catalog.yaml` (доставлена при выдаче).
2. `pack_catalog_url` из `params.yaml` → скачать.
3. Нет ни того ни другого → сказать пользователю: «Каталог паков не найден — запросите у владельца паков файл pack-catalog.yaml», СТОП.

Без аргумента → показать витрину таблицей: имя, домен, описание, доступ (open / by-subscription), для кого. **Исключить из витрины записи с `offered: internal-only`** (внутренние паки пилота — платформа, верификация, автономные агенты, правила агентов; видны только по точному имени в аргументе, не в общем списке). СТОП (ждать выбора).

### 2. Проверка перед подключением

- Пак есть в каталоге? Нет → «Пака нет в каталоге», показать витрину.
- `offered: internal-only` → отказать сразу, ДО проверки `access`: **«<имя> не выдаётся по подписке (внутренний пак)»**, СТОП. Явный запрос по точному имени не обходит это ограничение — иначе для паков, у которых репозиторий технически ещё публичен (`access: by-subscription` не защищает), `git ls-remote` в следующем пункте прошёл бы успешно и склонировал внутренний пак любому.
- Уже склонирован в `~/IWE/<имя>`? → «Уже подключён», предложить `git pull` для обновления.
- `access: by-subscription` → проверить доступ: `git ls-remote <url>` (или `gh repo view`). Отказ → сообщить: **«Нет доступа к <имя>: запросите право чтения у владельца (<owner>)»**, СТОП. Это штатное ограничение для тех, кто без подписки, не ошибка.

### 3. Подключение (цель: ≤1 минуты, замерить и сообщить время)

```bash
cd ~/IWE && git clone <url> <имя>
```

Затем три пометки:

1. **CLAUDE.md пользователя** — блок (создать при первой подписке, дальше пополнять список):

```markdown
## Подписанные паки (read-only)

> Чужие паки по подписке: читать и искать — да, править — НИКОГДА (только `git pull`).
> Нашёл ошибку/устаревшее → сообщить владельцу (issue), не исправлять молча.
> Адаптация → копия в СВОЙ пак с пометкой источника (пак, файл, версия/дата).

**Автообновление.** В начале любой новой рабочей сессии в этом репозитории — молча `git pull`
каждый пак из списка ниже (read-only копия, `pull` её не портит, разрешения спрашивать не надо).
Если пришли новые коммиты — одной строкой сказать, что обновилось; если нет — не упоминать вовсе.

**Область поиска по умолчанию (настройка — меняется прямо здесь).**
default_scope: all-connected
> `all-connected` — поиск идёт по своим знаниям и всем подписанным пакам сразу (сейчас так).
> `own-only` — поиск только по своим знаниям; подписанные паки — по прямой просьбе.
> Смена: скажи агенту «сделай по умолчанию own-only» (или наоборот) — он поправит строку
> `default_scope` выше сам; либо отредактируй её сама. Разовое отклонение от умолчания на
> один ответ — фразой «ищи только в моих» / «посмотри и в паках <владельца>», без смены настройки.

- `<имя>` — владелец <owner>, подключён YYYY-MM-DD
```

2. **Реестр репозиториев пользователя** — если в инсталляции есть реестр (`REPOSITORY-REGISTRY.md` или аналог) → строка: имя, класс Pack (подписка, read-only), владелец, дата. Нет реестра → пропустить молча (появится с гейтом создания репо, WP-527).

### 4. Памятка

Показать пользователю `templates/subscriber-memo.md` (целиком, это одна страница) и предложить сохранить копию в его рабочую папку.

### 5. Отчёт

Одной строкой: что подключено, сколько заняло, как искать, как обновлять. Если замер >1 минуты — зафиксировать в карточку WP-532 (нарушение цели H-293 п.1).

## Ограничения версии 0.2 (прототип)

- Отключение подписки: вручную (`rm -rf` клона + убрать строку из CLAUDE.md) — скилл-команда `unsubscribe` будет в следующей версии.
- Открытая витрина (каталог без доставки копии) — фаза сервиса (Ф3 WP-532).
- Автообновление и область поиска по умолчанию (0.2, 02.09) — это инструкция агенту в CLAUDE.md,
  не системный крон: срабатывает, когда пользователь открывает рабочую сессию в этом репозитории.
  День без единой сессии — обновления не будет; это осознанно принятое ограничение прототипа
  (см. `inbox/WP-532/WP-532.md` «Технические ориентиры» — полноценный крон/SLA требует ArchGate,
  этот прототип его не проходил).
