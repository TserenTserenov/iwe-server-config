# Month Close (протокол закрытия месяца)

> **Роль:** R1 Стратег (выполнение), R23 Верификатор (Haiku, чеклист). **Бюджет:** 30-45 мин.
> **Триггер:** последние дни закрываемого месяца (месяц фактически завершился или вот-вот завершится), либо первый Пн следующего месяца, если не сделано раньше — в обоих случаях перед Strategy Session первой недели.
> **Принцип:** Month Close = агрегация 4-5 Week Close'ов + переосмысление фазы/калибра. Не повторяет Week Close, опирается на его выходы.
> **Позиция в ВДВ v9:** стадия 7 «Закрытие месяца». Вход = Report W{N} предыдущего месяца + Strategy.md. Выход = Strategy.md § Результаты месяца (R1-RN) + `archive/MonthClose YYYY-MM.md`.
> **SKILL.md = L1 платформенный файл.** Пользователь не редактирует напрямую — только через `extensions/`.

## When to use

Протокол закрытия месяца (Month Close). Стадия 7 каскада ВДВ v9 (PD.METHOD.008). Запускается в последние дни закрываемого месяца или в первый Пн следующего месяца, до Strategy Session.

## БЛОКИРУЮЩЕЕ: пошаговое исполнение

Month Close = протокол. Исполнять ТОЛЬКО пошагово через TodoWrite.
**Шаг 0 — ПЕРВОЕ действие:** создать список задач прямо сейчас (до любых других действий).
Каждый шаг алгоритма → отдельная задача (pending → in_progress → completed).
Переход к следующему — ТОЛЬКО после отметки текущего. Шаг невозможен → blocked (не пропускать молча).

## Предусловия (проверить ДО запуска)

1. **Подходящее окно для Month Close?** Допустимо любое из: (а) последние дни закрываемого месяца — месяц фактически завершился или вот-вот завершится; (б) первый Пн следующего месяца (надстройка к еженедельной сессии), если не сделано раньше; (в) пропущенный Month Close за прошлый месяц — запускать до середины месяца с явным указанием периода. Вне этих окон (середина месяца без явного «пропущенный период») — предложить пилоту подождать до конца месяца, не блокировать намертво.
2. **Week Close предыдущей недели выполнен?** Report W{N-1} существует в `current/` или `archive/`. Если нет — СТОП, сначала `/week-close`.
3. **Month Close прошлого месяца архивирован?** `archive/MonthClose YYYY-MM.md` существует (для месяцев после MVP). Если нет (первый прогон мая 2026) — пропустить проверку.

### 1. Сбор данных (агент)

**Предзаготовка (WP-484 Ф5, если есть).** Проверить `DS-my-strategy/archive/MonthClose-facts-{YYYY-MM}.md` (тот же период, что определяется в 1a). Файл найден → прочитать `generated_at` из frontmatter. **Свежий** = `generated_at` не раньше конца месяца `{YYYY-MM}` (месяц завершился → факты полные; прогон в середине месяца, например ручной тест, даёт частичный срез — не финальный). Свежий → читать блоки 1b-1g ИЗ НЕГО вместо живого сбора ниже (тот же скрипт `scripts/month-close-scaffold.sh --as-of YYYY-MM` можно прогнать заранее вручную, если ещё не запускался автоматически). Файла нет, или `generated_at` раньше конца месяца → выполнять шаги 1a-1g ниже вручную, как раньше (никогда не блокировать Month Close частичной предзаготовкой — тот же принцип «нет данных → явный шаг, не тихая подмена»).

**1a. Период.** Определить границы месяца: `YYYY-MM-01 .. YYYY-MM-{last}` (фактически — последний Week Close предыдущего месяца).

**1b. Коммиты за месяц.**

```bash
for repo in $(ls {{HOME_DIR}}/IWE/); do
  if [ -d {{HOME_DIR}}/IWE/$repo/.git ]; then
    count=$(git -C {{HOME_DIR}}/IWE/$repo log --since="$MONTH_START" --until="$MONTH_END" --oneline --no-merges 2>/dev/null | wc -l)
    [ "$count" -gt 0 ] && echo "$repo: $count"
  fi
done
```

**1c. Week Report'ы месяца.** Собрать `current/Report W{N}.md` за 4-5 недель → список закрытых/перенесённых РП, мультипликаторы, ТОС недель.

**1d. Drift месячный.** `bash ${IWE_SCRIPTS:-$HOME/IWE/scripts}/iwe-drift.sh` → выявить пары, где lag вырос за месяц.

**1e. Decision log.** `DS-my-strategy/decisions/decision-log-YYYY-MM.md` (WP-109 Ф7, реализация: один файл на месяц) — решения, принятые за месяц.

**1f. Метрики файлов memory (WP-217 Ф10.2).**

```bash
bash ${IWE_SCRIPTS:-$HOME/IWE/scripts}/memory-health.sh
bash ${IWE_SCRIPTS:-$HOME/IWE/scripts}/memory-bleed.sh
```

HOT-лимит превышен → понизить horizon в frontmatter нужных файлов ДО дальнейших шагов. Кандидаты на понижение из bleed-отчёта → зафиксировать в `MonthClose YYYY-MM.md § T-чеклист T23`.

**1g. Стабильные входы (PD.METHOD.008 стадия 7 входы 5+6).** Прочитать `DS-my-strategy/docs/Dissatisfactions.md` (список НЭП) + `DS-my-strategy/docs/Projects.md` (список проектов P1-P6). Без них ревизия проектов (Шаг 4) и промоция новых R (Шаг 9) не имеют контекста.

### 2. Мультипликатор месяца

> Агрегация недельных мультипликаторов, НЕ среднее дневных.

1. **WakaTime месяца** — сумма физического времени за все дни месяца
2. **Бюджет закрыт за месяц** — сумма `Бюджет закрыт` из всех Week Report'ов месяца
3. **Мультипликатор месяца** = Бюджет закрыт / WakaTime. Формат: `N.Nx`
4. **Динамика** — сравнить с прошлым месяцем (рост / падение / стабильно)

### 3. Ретроспектива фазы и калибра (человек + агент)

**3a. Фаза стратегической позиции (PD.FORM.078).**

Текущая декларация в Strategy.md § Состояние месяца: [Development / Chaos / Ceiling / Pivot]. Проверить по 5 сигналам PD.FORM.078:
- Оправдались ли сигналы перехода, зафиксированные в начале месяца?
- Фаза стабильна, сдвинулась, или требует пересмотра?
- Решение: оставить / сдвинуть → записать в `MonthClose YYYY-MM.md`.

**3b. Калибр личности (PD.CHR.007).**

Текущий калибр в Strategy.md (например: 3, целевой 4 к концу 2026). Вопросы:
- Появились ли за месяц события/результаты, сигнализирующие рост?
- Разрыв по трём направлениям (горизонт / bus factor / публичность) — какой сократился?
- Пересчёт: оставить / поднять на 0.5 / потребовать дополнительных действий.

> **Ретро месяца** — см. шаг 0.5 (переставлено к началу, 30.07). Формулировка и поля идентичны `scripts/month-preclose.sh` — тот же скрипт остаётся терминальным запасным путём.

- Баланс часов по P — есть ли крен, соответствующий стратегии?

Вывод: 1-2 абзаца в `MonthClose YYYY-MM.md § Ревизия проектов`.

## Связь с другими масштабами ОРЗ

- **Не заменяет `/week-close`** — Month Close опирается на свежий Week Report предыдущей недели. Сначала `/week-close`, потом `/month-close`.
- **Предшествует Strategy Session первой недели** — её вход = только что обновлённый Strategy.md + `MonthClose YYYY-MM.md`. Не сливать в одну сессию: разные роли (R23 Верификатор для Close, R1 Стратег для Session) и разные артефакты.
- **Триггер вне каскада:** Strategy Session первой недели месяца требует, чтобы Month Close был пройден до неё. DayPlan первого Пн содержит две строки: «Month Close YYYY-MM» (0.75h) и «Strategy Session W{N}» (1-2h).
