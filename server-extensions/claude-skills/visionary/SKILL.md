# /visionary — Визионер, ступень 1 (только автор)

> **Scope:** фокус дня у пилота в беседе (утро из открытия дня и запрос в любой момент), запись исходов проб, месячное мерило.
> **Not in scope:** доставка в Telegram (решение пилота 20.11.2026: только через приёмник выпусков Вестника, РП-568 Ф19 — пока его нет, фокус дня показывается только в беседе); обзор новостей; пересборка рекомендации Портного; ступени 2–3 (подписчики, только Telegram — РП-622 Ф4–Ф5).
> **Role:** Визионер (DP.ROLE.127). Обещание — DP.SC.231. Сценарии С1, С4, С5а, С5б, С6 — в карточке роли.

## When to use

- Открытие дня вызывает режим `focus` через расширение `extensions/day-open.after.visionary.md` (С1).
- Пилот спрашивает «что я могу сегодня сделать по-новому?» (С4) — тот же режим `focus`, ответ в этой беседе.
- Пилот сообщает исход пробы: «принимаю / не подходит / попробовал / закрепляю / эффект такой-то» с номером пробы (С6) — режим `outcome`.
- Пилот или подсчёт ставки H-353 спрашивает мерило за месяц — режим `stats`.

## Preconditions

1. **Журнал проб пишется в изолированную копию репозитория стратегии этой беседы** (главная копия заморожена). `J_REPO` — путь из поля `isolated_worktree:` отметки открытой сессии этой беседы (`~/IWE/.iwe-runtime/sessions/<агент>-<id>.open`); если сессии с изолированной копией нет — открыть её штатно (`session-guard.sh open --isolate`, из папки репозитория стратегии). Запись публикуется тем же путём, что остальные правки беседы (коммит в изолированной копии и `ds-publish.sh`), до её закрытия.
2. Программа журнала: `JOURNAL="$HOME/IWE/DS-my-strategy/scripts/visionary-journal.py"` — вызывается всегда с `--repo "$J_REPO"`.
3. **Запрещено** отправлять фокус дня через `send_telegram_message`, служебный канал сигналов IWE (`iwe-tg`, `lib/telegram.sh`) или любым другим путём мимо приёмника выпусков Вестника.

## Algorithm

### Режим `focus` (С1, С4, С5а, С5б)

#### Шаг 1 — Собрать внутреннее

Input: дата (`date +%F`), файлы пилота.
Action: прочитать (только нужное, выдержками):
- Персона: `~/IWE/PD-persona/Lifework/` (миссия, личный устав, профессиональные принципы), `~/IWE/PD-persona/masteries.yaml`;
- дела: раздел плана на сегодня из DayPlan (`DS-my-strategy/current/DayPlan <дата>.md`), направления недели (`current/WeekPlan W*.md`, последний), РП P1 в работе (`docs/WP-REGISTRY.md`);
- затруднения: `docs/Dissatisfactions.md` (открытые), заблокированные РП (🚧 в реестре), уроки памяти за 7 дней (`memory/lessons_*.md`, по дате в имени или frontmatter);
- узкое место и материал дня Портного — **файловый вход ступени 1**: `~/IWE/DS-personal-guide/panel/<дата>.md` (узкое место, задание) и `guide/<дата>.md` (материал, упражнение);
- изменения внутреннего: закрытые за 7 дней РП (✅ в реестре со свежей датой), итог Наставника ИИ, если есть, закреплённые пробы (Шаг 3).
Output: краткий конспект «дела дня, затруднения, узкое место, что нового во мне».

**Нет файлов руководства за сегодня** → фокус дня пустой: ноль предложений с причиной «вход руководства недоступен» (предложение без «что изучить» нарушает форму фокуса дня); перейти к Шагу 6 с `--count 0`.

#### Шаг 2 — Собрать внешнее

Input: конспект Шага 1, раздел «Мир» сегодняшнего DayPlan.
Action:
- **внешнее общее:** ссылки и вывод раздела «Мир» DayPlan;
- **внешнее личное:** 1–3 веб-поиска по двум-трём главным делам или затруднениям дня (что нового в моделях, инструментах, методах для этого дела за последние недели). У каждой находки — ссылка и дата публикации; находка без даты или ссылки отбрасывается.
Output: список находок «что изменилось — ссылка — дата — вид (внешнее общее / внешнее личное)».

#### Шаг 3 — Память проб

Input: журнал.
Action: `python3 "$JOURNAL" --repo "$J_REPO" history --days 60`.
Output: открытые пробы, отклонённые (не предлагать снова без нового основания — новое основание = другая ссылка или более поздняя дата, чем у отклонённой), закреплённые (это «новое во мне» для Шага 4).

#### Шаг 4 — Сопоставить и отобрать 0–3

Input: Шаги 1–3.
Action: для каждой находки (и для каждого изменения внутреннего) спросить: к какому делу пилота она относится и что конкретно сегодня можно сделать иначе? Оставить не больше трёх, где есть всё: изменение с основанием, дело, проба на настоящей задаче, признак успеха, материал Портного для «что изучить и потренировать». Материал Портного — **цитатой со ссылкой «руководство, <дата>», без изменения содержания**; своего учебного совета вместо него не придумывать.
Output: 0–3 предложения. Ноль — честный ответ с причиной (С5а). Нет дел и целей (пустой план и нет РП в работе) — вместо предложений вопрос пилоту о его деле (С5б), ничего не записывать.

#### Шаг 5 — Показать один экран

Input: предложения Шага 4.
Action: вывести в беседе (и вставить разделом «Фокус дня» в DayPlan, если вызов из открытия дня):

```
## Фокус дня — что сделать по-новому (<ДД.ММ>)

1. **<что сделать по-новому>** — к делу <проект / РП / затруднение>
   Что изменилось: <одна фраза> (<ссылка>, <дата>; внешнее общее | внешнее личное | во мне)
   Почему для тебя: <одна фраза>
   Проба: <на какой настоящей задаче> · Получилось, если: <признак>
   Изучить и потренировать: «<цитата>» (руководство, <дата>)
   Похожие пробы: <номер и итог или «не было»>
   Номер пробы: VIS-<ГГГГММДД>-<N>

Ответ: «принимаю VIS-…», «не подходит VIS-…», позже — «попробовал VIS-…: <итог>», «закрепляю VIS-…».
```

Проба — приглашение, не задание. Без обзора новостей и без списка всего найденного.
Output: экран показан.

#### Шаг 6 — Записать

Input: показанный экран.
Action:
- каждое предложение: записать поля в файл (инструментом записи файлов, во временную папку беседы) и `python3 "$JOURNAL" --repo "$J_REPO" propose --json <файл>`; поля: `date, what_changed, basis, basis_date, source (internal|external_common|external_personal), work, why, trial, success_sign, study_origin, study_quote`. Номер, который вернула программа, — тот, что на экране (получить заранее: `new-id --date <дата>`);
- день: `python3 "$JOURNAL" --repo "$J_REPO" focus --date <дата> --count <N> --shown-in chat [--zero-reason "<причина>"]`;
- закоммитить `journal/visionary-trials.jsonl` в `J_REPO` и опубликовать вместе с остальными правками беседы.
Output: записи в журнале. Отказ программы (код 1) — исправить поля и повторить, не обходить.

### Режим `outcome` (С6)

Input: номер пробы и слово пилота.
Action: сопоставить слово с шагом и записать `python3 "$JOURNAL" --repo "$J_REPO" mark <номер> <шаг> [--result success|partial|fail] [--note "<заметка>"]`:
«принимаю» → `accepted`; «не подходит» → `declined`; «попробовал: …» → `outcome` с `--result` по словам пилота (неясно — спросить один раз); «закрепляю» → `fixed`; «не закрепляю» → `not_fixed`; «эффект: …» → `effect` с `--note`.
Программа сама держит порядок (нельзя «закрепляю» до «попробовал»); отказ — сказать пилоту, какого шага не хватает. Коммит и публикация — как в Шаге 6.
Output: строка в журнале; «already recorded» — повтор, не ошибка.

### Режим `stats`

Input: месяц `ГГГГ-ММ`.
Action: `python3 "$JOURNAL" --repo "$J_REPO" stats --month <месяц>` (журнал только читается — можно и в главной копии).
Output: проверенные пробы, закреплённые улучшения, новые результаты, дни с фокусом дня — раздельно. Число предложений мерилом не служит (DP.SC.231).

## Bundled resources

Нет: программа журнала живёт в репозитории стратегии (см. Preconditions, п.2).

## Anti-patterns

- Обзор новостей вместо 0–3 предложений с пробой.
- Учебный совет Визионера вместо материала Портного; пересказ цитаты своими словами.
- Отправка фокуса дня в Telegram до приёмника выпусков Вестника.
- Повтор отклонённого предложения без нового основания.
- Предложение без ссылки и даты основания.
- Запись в главную копию репозитория стратегии.
